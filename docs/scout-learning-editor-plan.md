## Increment 1 — a real, limited learning experiment and timing foundation

Build a small durable learning workbench beside the existing evidence ledger. Import the Mesa editorial decisions with exact source hashes and individual observations; also accept references to existing package-comparison observations. Do not label them human verification. Propose a lesson with its supporting IDs, counterexample, scope and exact baseline guidance snapshot.

Prepare two sealed experiment packets with identical cases and model configuration, one using existing guidance and the other the candidate instruction. Store assignment allowances, dispatch identity/time, complete/partial responses, actual context/model receipts and an explicit evidence-based assessment. Preserve raw input/output, validate every case ID, and report quality/time/cost separately. This increment cannot activate production guidance.

Add opt-in timing to checkpoint encode/decode, workflow reads/writes and database commit, with a compact report. Gather baseline measurements on an isolated fixture or snapshot; do not redesign the production store before reviewing the measurements.

Tests:

- Same editorial import twice creates no duplicate observations; conflicting IDs, bad hashes, missing mappings and incomplete source coverage fail without partial writes.
- Editorial judgments, observed human edits and field confirmations retain distinct provenance; an import cannot promote evidence strength.
- Lesson proposals require existing support, clear scope, counterexamples and an exact baseline snapshot. Proposing or evaluating never changes the playbook files or active guidance.
- Packet hashes detect tampering; test cases exclude explicit lesson-example IDs; expected answers and prior editor decisions do not appear in researcher packets.
- Both arms must use the same case set/model settings and distinct fresh context receipts. Partial replies, duplicate/missing case IDs and mismatched identities fail visibly or remain incomplete; retries do not duplicate results.
- Assignment limits, elapsed limits, late result capture, restart and immutable history work. Budgets are not counted as demonstrated coverage.
- An assessment needs both complete results and evidence-backed case judgments. Positive results remain evaluated/inactive. Missing cost stays unknown.
- Timing disabled preserves ordinary behavior; enabled records phases without resource text; timing-output failure cannot corrupt a transaction. Rollback/error events and existing compressed/legacy checkpoint compatibility remain tested.
- Run the relevant existing suites and then the full Python suite once the new checks pass.

Limited acceptance pilot: use a few real saved resource cases, with baseline/variant responses from fresh contexts when service access permits. Record exact provider/model access and limitations. If external access is unavailable, deliver the prepared trial and synthetic workflow tests, explicitly state that learning efficacy remains untested, and request only the missing access needed. Do not fabricate results.

## Increment 2 — measured checkpoint redesign

Use Increment 1 measurements to choose the smallest worthwhile change. Introduce immutable evidence storage and small task updates behind a new storage version. Keep a legacy reader and an explicit copy-first migration/rollback path. Measure the same representative operations before and after.

Tests: exact source/assignment/result hashes, transaction failure at each write, concurrent stale revisions, interrupted migration, legacy restart, curator histories/PDF bytes, and unchanged completion semantics. Assert that updating one task does not rewrite unrelated evidence; measure throughput and memory without brittle fixed-second unit tests. Do not claim an end-to-end speedup from a codec benchmark alone.

## Increment 3 — new-discovery editorial stages

Implement opt-in early suitability and final editorial stages in the actual discovery orchestration. Seal input scope and editor configuration; accept structured retain/combine/reserve/exclude decisions by candidate ID, validated field changes and concrete questions. Generate packages/HTML using existing application machinery. Preserve before/after records and feed the decisions to the learning workbench.

Tests: complete candidate accounting, program combinations/splits, meaningful alternatives, early-review uncertainty, no category quotas, five-section writing, all-field consistency, supported type/group changes, no invented verification, question/history and attachment preservation, restart at each stage, unchanged legacy path, actual editor/print/save/export and compatible-office merge. A small new-office/category pilot must exercise the full editor stage before broad use.

## Increment 4 — close the ordinary feedback loop and activate evaluated guidance safely

Connect incoming curator packages and question resolutions to a compact proposal queue using existing explicit lineage. Distill related observations into proposed methods with examples/counterexamples. Keep policy instructions and resource fact changes separate. Implement reviewed experiment/evaluated/active/rejected/superseded states, an atomic scoped active manifest and rollback. Resolve active guidance only into new or explicitly replanned assignments.

Tests: resolved/reopened/conflicting answers; repeated imports and shared evidence deduplication; partial absence; later provider changes versus earlier misses; rejected exclusions restored by curators; scope conflicts; activation requires recorded review and applicable evaluation; rollback/restart; historical runs remain sealed. No new scoring burden on curators and no automatic approval of the backlog.

## Increment 5 — learn efficient passes, model roles and sampling

Use evaluated outcomes to propose category/context-specific passes, stopping rules and model profiles. Compare models under fixed guidance and guidance changes under a fixed model. Expose actual outside-check workload, including overlapping categories. Evaluate scheduling improvements with sealed independent results and provider limits.

Tests: incomplete budgets cannot satisfy coverage, duplicate findings do not inflate value, sparse important needs survive, random versus targeted samples stay distinguishable, model upgrades do not silently rewrite old evidence, measured costs versus subscription allowance remain separate, and a new operating policy applies only after explicit review.
