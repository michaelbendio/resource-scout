# Implementation plan: learning-guided Astra research

**Status: approved for staged implementation on September 7, 2026.**
Implements the [design](scout-playbook-learning-design.md) in small, reviewable
steps on the existing `v2.0` branch. Each completed increment gets a short report
of what changed, what we learned and the next part of the grand plan.
Preserve the old autoMesaV2 execution as an archive and use a separate execution
for the new protocol. The first checkpoint is implementation and synthetic
verification of the research foundation, before the live Employment pilot.

## 1. Versioned execution and sampled comparisons

**Implementation:** [research foundation and operator notes](scout-astra-foundation.md).
The new protocol is opt-in and verified with synthetic trials; no new live
provider research is represented by those trials.

Extend the current guidance loader and maintenance workflow with explicit
Astra-only, targeted-challenger and independent-comparison roles. Use the actual
configured Astra model identity where available while retaining compatible stored
Codex researcher identifiers. Resolve category playbooks into assignments and
preserve role/configuration snapshots. Existing jobs keep their original behavior.

Add the neutral Claude packet path, immutable Astra-only freeze, reproducible
category sampling and required-check completion semantics. Define complete
stage/output contracts rather than disabling existing auditors by omission.
Store sampling/planning configuration as data. Do not create another parallel
playbook library. Keep current human approval/export protections.

**Acceptance:** a synthetic job with zero outside checks can reach research-ready;
a selected comparison job cannot do so until its actual comparison and dispositions
are saved. Both resume with the same assignments and sample.

**Tests:** unchanged legacy stage sequences; primary-only finalization; correct
selected roles; no researcher-result misattribution; deterministic sampling and
scope amendments; neutral packets exclude primary/challenger answers and learned
search hints; guidance/manifest hash validation; immutable frozen results; restart
after every stage; missing provider remains pending; transaction rollback and
explicit protocol-change history. Reject a complete claim for an incomplete packet.

**Recovery:** retain the old execution revision and output; a failed migration
leaves it untouched. New runtime records and browser artifact identities are
isolated before any real research.

## 2. Mesa Employment demonstration

Run the existing enhanced Employment focuses against the explicit Mesa baseline.
Make an initial pass plan and record why each pass is useful. Allow documented
follow-ups without claiming automatic adaptation. Freeze Astra's complete result,
then collect Claude's neutral independent research. Verify material contributions
and preserve Astra-only and assisted outcomes separately. Use targeted challengers
only when a specific issue warrants them.

Produce a separate review HTML using the full existing application and all three
editors. Show a small varied selection: straightforward provider, shared intake,
multiple program types, source conflict and an access-barrier case. The pilot is
an operational demonstration; prior exposure prevents a clean new-discovery claim.

**Acceptance:** Michael can inspect a concise summary with bold changes and
understand what Claude added or corrected. The curator can edit, print, mark
Curated and export the exact selected revision. Provider research readiness is
not mistaken for completed human curation.

**Tests:** service corrections propagate to description/Information/classification;
useful unique facts survive rewriting; unresolved contradictions reach curator
questions; no research commentary leaks into handouts; full Category/Type, For and
Resource editing; both browse routes; no hidden group exclusion claim; edits
invalidate Curated; regeneration preserves local edits; exact selected export and
merge into a disposable office copy preserve IDs, history, unrelated resources and
PDFs. Inspect actual screen and print output. Reuse existing checks where they
already cover behavior; add focused regressions for changed paths.

Explicitly test resolved-question persistence across two isolated application
instances: resolve and export a selected resource in autoMesaV2, merge into a
disposable mesa.html built from the updated common code, save/reload, export the
office package, and import it into Scout. Assert exact question IDs, answers,
statuses, sources and dated histories at every step, including repeat imports.
An older open question and a newer resource edit without question fields must
not erase the answer; concurrent conflicting answers must retain both for review.
The current iCloud mesa.html lacks this merge support, so deploying the compatible
office application is a delivery requirement, not an assumption about old files.

**Feedback checkpoint:** Michael reviews the design/output. Arrange normal curator
print/call feedback through the established workflow when available; do not contact
anyone automatically or invent a completed vetting trial. Broader research may
proceed under approval with that feedback explicitly pending.

## 3. Proposed lessons and a bounded experiment

Connect validated comparison findings and attributable human observations to
structured lesson proposals. Start with a few recurring, consequential misses.
Each names its cause, counterexamples, existing-instruction check and exact proposed
JSON/Markdown change. Show representative evidence, not a full-package review dump.

Implement proposed/experiment/evaluated/approved-active/rejected/superseded states
and an atomic active manifest. Experiment approval does not activate production
guidance. No automatic activation from an evidence-ledger status or a raw AI claim.

**Acceptance:** a proposed revision can be tested against the previous version on
withheld examples or a new community, with comparable conditions and a concise
comparison of coverage, errors and time. Michael can approve a scoped version or
keep the current one; rollback preserves all evaluations.

**Tests:** raw findings cannot become verified evidence; repeated imports do not
multiply examples; partial absence and later openings are not discovery misses;
human edits are not inferred telephone confirmations; answer identities stay out
of general guidance/test contexts; experimental versions stay inactive; conflicting
scope fails validation; existing assignments retain old instructions; atomic
activation/rollback; rejected and superseded evidence remains traceable.

## 4. Resume autoMesaV2 with measured sampling

After the Employment review, record which old results are reused, replaced or
still pending. Prepare the new execution manifest and sample the remaining
category assignments at the reviewed rate. Collect old in-flight replies only as
old-protocol evidence. Continue useful research with periodic category reports.

**Acceptance:** reports identify actual methods and independent coverage, waiting
time and active time, plus unresolved needs. No retroactive attribution of old
work to the new playbook. Give a new ETA after measured categories; earlier
50-60-hour estimates do not apply unchanged to this redesigned run.

**Tests:** repeated restart does not redispatch completed work or reroll sampling;
cross-category identity review uses the original whole-office index and attributable
proposals; missing selected Claude output cannot silently become unsampled work;
merging/reclassification updates coverage accounting; output stays unapproved until
the normal curator/package process.

## 5. Learn pass selection and stopping

Use accumulated evaluated outcomes to propose category/context-specific changes
to passes, budgets and sampling rates. Distinguish failed execution of an adequate
instruction from a missing research method. Avoid pooling incompatible offices,
models, budgets or playbook versions. A single empty pass does not retire a focus.

**Acceptance:** Scout can explain an extra, revised or omitted pass with relevant
evidence, preserve important sparse coverage, and distinguish a budget stop from
sufficient research. Demonstrate value on unfamiliar material before claiming
less wasted research or comparable reliability.

**Tests:** high raw counts cannot hide an unmet coverage obligation; duplicates and
rewrites do not inflate discovery yield; critical unresolved matters survive low
yield; budget exhaustion records gaps; inadequate history retains baseline policy;
updated settings affect only new or explicitly replanned assignments; random and
targeted evaluation results remain statistically distinguishable.

This is the remaining adaptive portion of grand-plan increment 6. It should be
designed in more detail using the actual experience of the preceding steps.
