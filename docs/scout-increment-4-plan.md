# Increment 4: maintain the collection

Authorized after Michael accepted the simplified 3C navigation. Work stays on
Scout v2.0. The location-app release remains a separate pending step; maintenance
must not require an unapproved category retirement or overwrite its preview.

## Deliverable

A first-class Maintenance page and operator commands start from an explicitly
selected office package. Each run freezes its scope, research policy, writing
guidance, researcher roster, and source package. Known-resource rechecks and
category searches for additions have separate coverage and resume independently.
Codex researches and reconciles; ChatGPT, Grok, and Perplexity independently audit.
Software fixtures must never be described as those services' actual research.

Rechecks distinguish current, changed, moved, renamed, paused, possibly closed,
reopened, inconclusive, and identity/program-boundary problems. Preserve sources,
source dates, follow-up questions, and proposed next-check dates. A broken URL
alone cannot justify a closure proposal. Search results are matched against the
current package, tombstones, and prior accepted/declined maintenance proposals.
Possible duplicates and reopenings require explicit identity review.

Review shows current/proposed fields and dated evidence. Partial reviewed updates
and additions may export while other checks await research or a phone call.
Reconnect the latest package first; detect later same-field edits and invalidate
stale reviews. Preserve stable IDs, local notes, PDFs, history, and verifiedOn.
A closure decision exports only a pending deletion request, leaving the resource
in place for the location app's existing deletion-review workflow. Never infer
closure from failed contact, automatically delete a resource, or recreate a
retired ID as a new resource.

Research strategy stays in JSON/Markdown. This increment records observations
and human outcomes; it does not activate learning, adapt run counts, schedule
background work, or start real office research automatically.

## Tests and review

Exercise moved/renamed/paused/closed/reopened/inconclusive/current cases, failed
URLs, identity matches against current/retired/declined records, new additions,
all required audits, exact reconciliation, restart/resume, scoped coverage,
newer human edits, wrong-office/stale packages, retired IDs, canceled exports,
repeat exports, acknowledgment, exact PDF bytes, and safe unknown fields.
Test HTTP and CLI entry points plus the real browser review/export path with
explicitly synthetic data in a disposable database. Run the full Scout suite.

Then review a small historical-development example before starting an authorized
real maintenance pilot. The next increment in the grand plan is 5: proposed
research-method lessons from attributable human-vetted outcomes, kept inactive
until separately reviewed. Increment 6 later adapts category assignments.
