# DeepSeek Housing preparation and review trial

Michael requested the after-curation candidates from the completed Housing pilot,
with DeepSeek doing curation and then review using Codex's substantive instructions.
This authorizes a Housing-only early preparation trial. It does not complete the
implementation plan's later three-category, twenty-item evaluation, authorize a
production import, or reopen other Mesa work.

Input: all 104 original DeepSeek Housing leads and their original source evidence.
No historical prepared resources or Codex pilot findings are supplied as an answer
key. Eight-lead batches retain every candidate disposition. DeepSeek V4.1-Flash
uses max effort, targeted native search and public-page fetches. A complete
collection judgment follows preparation. The draft is frozen before fresh review
contexts receive it and the original evidence. Review findings retain before/after
statements, sources and unresolved issues; a second collection judgment checks
identities, taxonomy, gaps, starters and considerations.

The current prepared-resource contract supplies five Information sections and
explained 7–10 starter sets. The original Codex checklist is supplied verbatim with
its legacy four-section/tier instructions explicitly superseded. Deterministic
checks establish structural coverage, not the quality of DeepSeek's judgments.
Using the same model twice can preserve shared blind spots. No Codex review or
independent source-audit completion is claimed.

Outputs are evaluation JSON and escaped read-only HTML, preserving both stages.
Provisional program records remain visible even where the collection judgment
groups aliases; these are proposed identity decisions, not production registry
merges. This is deliberately not `prepared-resources.json`. Every JSON preview
has `evaluationOnly: true`, `importable: false`, a distinct evaluation artifact
type and no human approval. Production records and registry stay untouched.

The user's removal of the Housing dollar cap continues for this requested trial.
Each request still has recorded authorization, a saved request and raw response,
150-request / four-active-hour total bounds, a 600-second request timeout,
12 successful native searches per assignment, and existing unknown-outcome holds.
Unknown billing stays unknown. The supervisor checks the live process and new
events at least every minute and updates ETA after each completed batch once two
timings are available. Curation estimates exclude collection selection and review.

Runner: `python3 -m resource_research_agent.evaluation.preparation`.
Initialize with `--initialize-from RESEARCH --code-commit COMMIT --experiment TRIAL`;
execute/resume with `--experiment TRIAL --execute`. A nonblocking process lock
prevents duplicate coordinators. Completed calls are adopted from immutable saved
results. Never reset a held assignment or repeat an uncertain paid request without
diagnosis and preserved recovery evidence.

Validation before launch: 49 prior evaluation tests and 31 affected preparation,
prepared-resource, identity and new trial tests pass. Runtime evidence and completion
findings will be recorded after the trial.
